PART I — THE LANGUAGE

Module 0 — What is a computer, really?

0.1 A computer is a very fast, very dumb clerk

Explain it like I'm 8

Imagine a huge wall of mailboxes. Every mailbox has a number (its address) and holds a tiny note. Next to the wall sits a clerk who can only do things like: "read the note in box 5", "add two notes", "write a new note into box 9", "if this note is zero, jump to instruction 40." That's it. The clerk is stupid but does billions of these per second.

The wall is memory (RAM). The clerk is the CPU. A program is a long list of instructions for the clerk.

Why do computers use only 0 and 1? A wire is either carrying voltage or it isn't. Two states are easy to build and very reliable (no confusion between "almost on" and "a bit on"). Each 0/1 is a bit. Eight bits make a byte (one mailbox holds one byte).

How many different notes can a byte hold? Each bit has 2 choices, 8 bits: $2^8 = 256$. So a byte holds 0…255.

Counting in binary

We count in tens because we have ten fingers: the digit's place is worth 1, 10, 100, … Binary is the same with two fingers: places are worth 1, 2, 4, 8, 16, … 1011₂ = 8 + 0 + 2 + 1 = 11₁₀. To convert 13 to binary: 13 = 8+4+1 → 1101.

0.2 Why can't the CPU read C++?

The CPU understands only machine code — numbers meaning "add", "load", "jump". Writing that by hand is miserable, so humans invented languages like C++ and a translator called the compiler.

flowchart LR
  S[your .cpp text] -->|preprocessor| P[expanded text]
  P -->|compiler| O[object file .o<br/>machine code pieces]
  O -->|linker| E[executable program]
  L[library code<br/>e.g. iostream] --> E
  1. Preprocessor: handles lines starting with #. #include <iostream> literally pastes the contents of that file in. (Dumb copy-paste, before anything is understood.)
  2. Compiler: checks your grammar (syntax) and types, then translates to machine code. This is where "compile errors" come from.
  3. Linker: stitches your pieces and library pieces into one program. "undefined reference" errors come from here — you promised a function existed but never supplied it.
  4. Run: the OS loads the program into memory and the CPU executes it. "Segmentation fault" and wrong answers come from here (runtime errors).
Why does C++ have a compile step at all (unlike Python)?

Because translation happens once, ahead of time, with the compiler free to spend seconds optimising. Python translates while running, repeatedly. That's why C++ is typically 10–100× faster, and why competitive programmers love it. The price: you must be precise, and C++ trusts you not to make mistakes — it will not stop you from stepping off a cliff.

Module 1 — Basics: variables, types, operators, I/O

1.1 Your first program, every character explained

#include <iostream>          // (1)
using namespace std;         // (2)
 
int main() {                 // (3)
    cout << "Hello, world!" << endl;   // (4)
    return 0;                // (5)
}
  1. #include <iostream> — paste in the declarations for input/output (cin, cout). Without it the compiler has never heard of cout.
  2. using namespace std; — the standard library lives in a "family name" std. Fully you'd write std::cout. This line says "assume the family name std so I can drop it." Fine for learning/contests; in big projects people avoid it because two libraries might both define a name sort, causing confusion.
  3. int main() — every program starts here. int means it hands back a whole number to the OS when done.
  4. cout << ... — "character out". << is the arrow pushing data into the output stream. endl ends the line (and flushes — see §1.8).
  5. return 0; — tells the OS "all went fine". (Non-zero means error. Writing it in main is optional; the compiler adds it.)

Every statement ends with ; — a period for the compiler. Why? So the compiler knows where one instruction ends even if you spread it over many lines.

1.2 Variables: named mailboxes

int age = 17;

Read it as: "Reserve a box big enough for a whole number, call it age, put 17 in it."

A variable has four things — know them cold:

Thing For int age = 17;
Name age
Type int (decides size and how bits are interpreted)
Value 17
Address where in memory the box lives (e.g. 0x7ffc...)
Why types exist

A byte holding 01000001 is just 8 bits. Is it the number 65? The letter 'A'? Part of a decimal number? The bits don't know. The type tells the compiler how to interpret them. Types are the dictionary.

Fundamental types

Type Typical size Range / use
bool 1 byte true / false
char 1 byte one character, as a small number (−128..127)
short 2 bytes ±32 767
int 4 bytes ±2 147 483 647 (about ±2.1×10⁹)
long long 8 bytes ±9.2×10¹⁸
unsigned int 4 bytes 0 … 4 294 967 295
float 4 bytes ~7 decimal digits of precision
double 8 bytes ~15–16 decimal digits 
#include <iostream>
#include <climits>
using namespace std;
int main() {
    cout << "int: " << sizeof(int) << " bytes\n";
    cout << "long long: " << sizeof(long long) << " bytes\n";
    cout << "INT_MAX = " << INT_MAX << "\n";
    cout << "LLONG_MAX = " << LLONG_MAX << "\n";
}
Sizes are "typical", not guaranteed

The standard only promises sizeof(char)==1 and short ≤ int ≤ long ≤ long long. On virtually all modern machines int is 4 bytes, but that's a fact about the machine. Use sizeof or fixed-width types (int32_t, int64_t from <cstdint>) when it matters.

1.2.1 Why does int have a limit? And what happens when you exceed it?

4 bytes = 32 bits = $2^{32}$ ≈ 4.29 billion patterns. Half are used for negatives, so −2³¹ … 2³¹−1.

How negatives are stored — two's complement. Imagine an odometer with 3 wheels showing 000…999. Roll back one from 000 and you get 999. So 999 can pretend to be −1. Computers do this in binary: with 8 bits, 11111111 is −1, 11111110 is −2, …, 10000000 is −128. The top bit tells the sign. Why this trick? Because then the same adder circuit adds positive and negative numbers — no special hardware for subtraction. Beautiful.

8-bit signed:  01111111 = 127   +1 →  10000000 = -128   (wraps!)
Overflow

int x = INT_MAX; x = x + 1; is undefined behaviour for signed integers: the standard says "anything may happen" (in practice it wraps to negative, but the compiler is allowed to assume it never happens and optimise accordingly, producing bizarre results). For unsigned types, wrapping is well-defined (arithmetic modulo $2^{n}$). Contest rule of thumb: if a value might exceed ~2×10⁹ (e.g. a sum of 10⁵ numbers each up to 10⁵, or a product), use long long.

1.2.2 float and double: why 0.1 + 0.2 ≠ 0.3

You can write 1/3 in decimal only as 0.3333… (infinite). Similarly, in binary, 0.1 is 0.000110011001100… forever. A double has 53 binary digits of significand, so it must cut off — a tiny error.

#include <iostream>
#include <iomanip>
using namespace std;
int main() {
    double a = 0.1 + 0.2;
    cout << setprecision(20) << a << "\n";   // 0.30000000000000004441
    cout << (a == 0.3 ? "equal" : "NOT equal") << "\n";
    // Right way to compare: allow a tiny tolerance
    cout << (abs(a - 0.3) < 1e-9 ? "close enough" : "different") << "\n";
}
Rule

Never compare floating-point numbers with ==. Compare abs(a-b) < eps. Prefer integers whenever the problem allows.

1.2.3 char is secretly a number

char c = 'A';
cout << c << " " << (int)c << "\n";   // A 65
cout << (char)(c + 1) << "\n";         // B

Computers store letters as numbers via ASCII: 'A'=65 … 'Z'=90, 'a'=97 … 'z'=122, '0'=48 … '9'=57. This makes the classic tricks work: - digit char → number: '7' - '0' = 55 − 48 = 7 - lowercase → uppercase: c - 'a' + 'A' (difference is 32) - letter index: c - 'a' gives 0..25 (used constantly in string problems)

1.2.4 bool, auto, const

bool isEven = (10 % 2 == 0);   // true; prints as 1
auto x = 3.5;                  // compiler deduces double
const int MOD = 1'000'000'007; // can never be changed; ' is a digit separator
Why `const`?

Two reasons: (1) it documents intent — "this never changes"; (2) the compiler enforces it, so a typo that modifies it becomes a compile error instead of a 3 a.m. bug.

1.2.5 Initialisation: the trap

int a;        // UNINITIALISED local: contains leftover garbage bits!
int b = 0;    // good
int c{};      // also 0 (brace init)
int d{5};     // 5, and braces refuse narrowing: int e{3.7}; is an ERROR (good!)
Why isn't everything auto-zeroed?

Zeroing costs time, and C++'s philosophy is "you don't pay for what you don't use." The box just holds whatever was there before. Global variables, however, are zero-initialised (they live in a special region cleared at startup). Always initialise locals.

1.3 Operators

int a = 7, b = 2;
a + b   // 9
a - b   // 5
a * b   // 14
a / b   // 3    ← integer division!
a % b   // 1    ← remainder
Why is `7/2 == 3`?

If both operands are int, the result type is int; the fractional part is truncated toward zero (so -7/2 == -3). The compiler decides the operation by looking at the types, not the values. To get 3.5: 7.0/2 or (double)a/b. Gotcha: double r = 7/2; gives 3.0, because the division happens first in integers.

Remainder with negatives: -7 % 3 == -1 in C++ (sign follows the left operand), unlike Python. To get a non-negative remainder: ((x % m) + m) % m.

Shortcuts: x += 5 ≡ x = x + 5. i++ means "add 1" (post: use old value then add; pre ++i: add then use). In a standalone statement they're identical; prefer ++i.

Comparison: == != < > <= >=. Logic: && (and), || (or), ! (not).

`=` vs `==`

if (x = 5) assigns 5 to x and is always true. Classic bug. -Wall warns you. (Some people write 5 == x so a typo becomes an error.)

Short-circuit: in A && B, if A is false B is never evaluated (the answer is already false). Why does it matter? if (i < n && arr[i] > 0) is safe — when i >= n, the array is never touched. Swap the order and you read out of bounds.

1.3.1 Bitwise operators (essential for DSA)

Operate on the individual bits:

Op Meaning Example (4-bit)
& AND — 1 if both 1 1100 & 1010 = 1000
\| OR — 1 if either 1100 \| 1010 = 1110
^ XOR — 1 if different 1100 ^ 1010 = 0110
~ NOT — flip all ~0101 = 1010
<< shift left 0011 << 2 = 1100 (×4)
>> shift right 1100 >> 2 = 0011 (÷4)
Why is `x << k` the same as `x * 2^k`?

In decimal, shifting digits left (37 → 370) multiplies by 10. Same idea in base 2, multiplying by 2 per shift.

Useful idioms (we'll prove why later in Module 17): - is bit i set? (x >> i) & 1 - set bit i: x |= (1 << i); clear: x &= ~(1 << i); toggle: x ^= (1 << i) - is x a power of two? x > 0 && (x & (x-1)) == 0

1.3.2 Precedence (who goes first)

* / % before + -; comparison before && before ||. Bitwise & has lower precedence than ==: x & 1 == 0 means x & (1==0) — a bug! When in doubt, use parentheses. They cost nothing.

1.4 Input and output

#include <iostream>
using namespace std;
int main() {
    int n;
    cout << "Enter a number: ";
    cin >> n;                      // reads whitespace-separated token
    cout << "Square = " << n * n << "\n";
}

cin >> n skips spaces/newlines, then parses characters into the type of n. For a full line with spaces use getline(cin, s); (note: after cin >> n a newline remains in the buffer; call cin.ignore() first).

1.4.1 Fast I/O (contest-critical)

By default cin/cout stay synchronised with C's scanf/printf (so mixing both works), which is slow. If you use only C++ streams, switch the sync off:

ios::sync_with_stdio(false);  // don't sync with C streams
cin.tie(nullptr);             // don't flush cout before every cin

and use '\n' rather than endl (endl forces a flush — a slow trip to the screen — every time). For 10⁶ numbers this is the difference between 0.1 s and 1+ s.

1.5 Type conversion (casting)

int a = 5;
double d = a;          // implicit, safe: 5.0
int b = 3.9;           // implicit, loses data: b == 3 (truncates)
int c = (int)3.9;      // C-style cast
int e = static_cast<int>(3.9); // C++ style: searchable, explicit

When types mix in arithmetic, the smaller/"weaker" one is promoted: int + double → double; int + long long → long long; and a notorious trap: int vs unsigned compares as unsigned, so -1 < 1u is false (−1 becomes 4 294 967 295).

The `size()` trap

v.size() is unsigned. for (int i = 0; i <= v.size() - 1; i++) when v is empty: size()-1 wraps to 18 446 744 073 709 551 615 → infinite loop/crash. Write i < (int)v.size() or i + 1 < v.size().

Try it — Predict

What do these print? cout << 5/2 << " " << 5/2.0 << " " << 5%3 << " " << -5%3 << " " << (1<<4);

Solution

2 2.5 2 -2 16. Integer division truncates; 5/2.0 is double; -5%3 is −2 (sign follows the left operand); 1<<4 = 16.

Module 2 — Control flow: making decisions and repeating

Kid version

Up to now the clerk follows instructions top to bottom like a recipe. Control flow lets the recipe say "if the milk is sour, throw it away" (decision) and "stir until smooth" (repetition).

2.1 if / else

int marks = 72;
if (marks >= 90)      cout << "A\n";
else if (marks >= 75) cout << "B\n";
else if (marks >= 60) cout << "C\n";
else                  cout << "F\n";

Conditions are checked top to bottom, first true wins. So >= 90 first, then >= 75 (which we reach only if it's not ≥ 90). Order matters.

In C++, any number works as a condition: 0 is false, everything else is true. That's why if (x) means if (x != 0).

Always use { } braces even for one line — a famous bug (Apple's "goto fail" security flaw) came from a missing brace.

Ternary: int m = (a > b) ? a : b; — a compact if-else that produces a value.

2.2 switch

switch (op) {
    case '+': r = a + b; break;
    case '-': r = a - b; break;
    default : r = 0;
}
Why `break`?

Without break, execution falls through into the next case. This is a deliberate historical design (sometimes handy for grouping cases) but a common bug. switch works on integers/chars, not strings.

2.3 Loops

while — repeat while a condition holds

int n = 5, fact = 1;
while (n > 1) { fact *= n; n--; }
cout << fact;   // 120

for — when you know the counting

for (int i = 0; i < 5; ++i) cout << i << " ";   // 0 1 2 3 4

for (init; condition; update) expands to: do init once; while condition { body; update }. Programmers count from 0 and use < because a length-5 array has indices 0..4 — "start at 0, stop before n" gives exactly n iterations with no off-by-one math.

do-while — runs at least once; range-for — over containers

vector<int> v = {3, 1, 4};
for (int x : v) cout << x << " ";        // copies each
for (int &x : v) x *= 2;                  // reference: modifies original
for (const auto &x : v) cout << x;        // read-only, no copy

break and continue

break leaves the loop entirely; continue skips to the next iteration.

2.4 Thinking about loops: invariants

How to write loops that are *correct*

Don't code by trial and error. Ask: "What is true at the start of every iteration?" — the loop invariant. Example, summing 1..n:

int sum = 0;
for (int i = 1; i <= n; ++i) sum += i;

Invariant: before iteration i, sum = 1 + 2 + … + (i−1). True initially (i=1, sum=0, empty sum). Each iteration preserves it. When the loop ends (i = n+1), sum = 1+…+n. ∎ This is exactly mathematical induction, and it's how you debug and prove algorithms.

Nested loops multiply: outer 3 × inner 4 = 12 executions of the inner body. Patterns:

for (int i = 1; i <= 4; ++i) {          // rows
    for (int j = 1; j <= i; ++j) cout << "* ";
    cout << "\n";
}

2.5 Worked examples

Is n prime? A number > 1 with no divisors except 1 and itself. Why only check up to √n? If $n = a \cdot b$ with $a \le b$, then $a \le \sqrt n$. So any composite has a divisor ≤ √n; if none found there, it's prime.

#include <iostream>
using namespace std;
bool isPrime(int n) {
    if (n < 2) return false;
    for (long long d = 2; d * d <= n; ++d)    // d*d<=n avoids sqrt rounding
        if (n % d == 0) return false;
    return true;
}
int main() {
    for (int i = 1; i <= 20; ++i) if (isPrime(i)) cout << i << " ";
    cout << "\n";   // 2 3 5 7 11 13 17 19
}

GCD (Euclid, ~300 BC): $\gcd(a,b)=\gcd(b,\ a \bmod b)$. Why? Any number dividing both a and b also divides a − qb = a mod b, and vice versa — so the set of common divisors is unchanged, and the numbers shrink fast.

int gcd(int a, int b) { while (b) { int t = a % b; a = b; b = t; } return a; }
Try it
  1. Print the digits of a number in reverse (use % 10 and / 10). 2. Sum of digits. 3. Print an inverted triangle and a number pyramid. 4. FizzBuzz 1..100.
Hint for 1 & 2

n % 10 is the last digit; n / 10 removes it. Loop while n > 0.

Module 3 — Functions: giving a recipe a name

Kid version

If you keep writing "crack egg, whisk, pour in pan" you'd go mad. Give the routine a name — makeOmelette — and just say the name. A function is a named recipe that takes ingredients (parameters) and may hand you back a dish (return value).

#include <iostream>
using namespace std;
int square(int x) {     // return type, name, (parameter list)
    return x * x;
}
int main() { cout << square(5); }   // 25
  • void return type = "returns nothing".
  • Arguments are the real values you pass; parameters are the names inside.

3.1 The call stack: what really happens

When main calls square(5), the machine: 1. sets aside a block of memory called a stack frame for square (holding its parameters and local variables and where to return to), 2. runs it, 3. discards the frame on return.

Frames pile up like a stack of plates: last in, first out.

 main()            ← bottom
   └ f()
       └ g()       ← top: currently running
Why a stack?

Function calls are naturally nested: you finish the most recent call before returning to its caller. A stack gives exactly that order, and allocating/freeing is nearly free (just move a marker). This also explains: local variables vanish when the function returns, and infinite recursion → stack overflow (plates pile past the ceiling; the stack is only ~1–8 MB).

3.2 Pass by value vs by reference

#include <iostream>
using namespace std;
void bad(int x)  { x = 99; }       // x is a COPY
void good(int &x){ x = 99; }       // x is another NAME for the caller's variable
int main() {
    int a = 1;
    bad(a);  cout << a;   // 1
    good(a); cout << a;   // 99
}
Why copies by default?

Safety: a function can't accidentally wreck your variables. Cost: copying. Copying an int is nothing; copying a vector of a million elements is expensive. So for big objects pass const T& — "give me a read-only view, don't copy":

long long sum(const vector<int>& v) { long long s=0; for(int x:v) s+=x; return s; }

Rule: small built-in types by value; big objects by const & (read) or & (modify).

Swap needs references:

void mySwap(int &a, int &b) { int t = a; a = b; b = t; }   // or std::swap

3.3 Declaration vs definition, overloading, defaults

#include <iostream>
using namespace std;
int add(int a, int b);            // declaration (prototype): "this exists"
int main() { cout << add(2,3); }
int add(int a, int b) { return a + b; }   // definition: the actual body

C++ reads top to bottom; you must announce a function before using it. Big programs put declarations in headers (.h) and definitions in .cpp files — the linker joins them.

Overloading — same name, different parameter types (the compiler picks by the arguments):

int    mx(int a, int b)       { return a > b ? a : b; }
double mx(double a, double b) { return a > b ? a : b; }

Default arguments: void greet(string name, string msg = "Hello");

3.4 Scope and lifetime

  • Scope = where a name is visible: from its declaration to the closing } of its block.
  • Lifetime = how long the box exists. Locals: until the block ends. static locals: whole program (initialised once). Globals: whole program.
int counter() { static int c = 0; return ++c; }  // remembers between calls

A variable in an inner block shadows an outer one of the same name — legal but confusing; avoid.

3.5 inline, constexpr, lambdas (preview)

  • inline: a hint/permission to paste the body at the call site (avoids call overhead). Modern compilers decide this themselves with -O2.
  • constexpr int sq(int x){return x*x;} — can be computed at compile time.
  • Lambda — an unnamed function you write on the spot:
auto add = [](int a, int b) { return a + b; };
cout << add(2, 3);

The [ ] is the capture list: which outside variables the lambda may use ([=] copy all, [&] reference all, [&x] just x by reference).

4.1 Arrays

Kid version

One mailbox holds one number. What if you need 100 test scores? An array is 100 mailboxes side by side, glued together, sharing one name, and numbered 0, 1, 2, …

int a[5] = {10, 20, 30, 40, 50};
cout << a[0] << " " << a[4];     // 10 50
a[2] = 99;

Why indices start at 0. The array's name stands for the address of its first box. Element i lives at address + i × (size of one element). The first element is zero steps from the start. So a[i] really means "start + i steps". That's the entire reason.

address:  1000  1004  1008  1012  1016        (int = 4 bytes)
value:    [10] [20] [30] [40] [50]
index:      0     1     2     3     4

Why arrays are fast: to reach a[i], the CPU does one multiplication and addition — the same time for a[0] or a[999999]. This is random access, O(1). Hold on to this; it's the superpower of arrays.

C++ does NOT check bounds

a[5] for a 5-element array reads whatever lies after the array — undefined behaviour: maybe garbage, maybe a crash, maybe it silently corrupts another variable. Why no check? Checking costs time on every access; C++ trusts you. Debug with -fsanitize=address or use v.at(i), which throws an exception.

2D arrays are "an array of arrays", stored row after row (row-major):

int g[3][4] = {};        // 3 rows × 4 columns, all zero
g[1][2] = 7;
Why traverse rows in the outer loop?

Memory is read in chunks (cache lines, ~64 bytes). Walking along a row touches neighbouring bytes — one chunk serves many reads. Walking down a column jumps far apart each time — a new chunk every read. Same answer, but row-wise can be several times faster. (Real-world speed isn't only about Big-O!)

Global big arrays: int dp[1000005]; as a global is fine (lives in static memory, zeroed). The same declared inside main lives on the ~8 MB stack and can overflow it — a classic crash for arrays beyond ~10⁶ ints.

Weakness of arrays: the size is fixed at compile time, and you can't grow them. Enter…

4.2 std::vector — the array that can grow

#include <vector>
vector<int> v;               // empty
v.push_back(5);              // append
v.push_back(7);
cout << v[0] << v.size();    // 5 2
vector<int> w(10, 0);        // 10 zeros
vector<vector<int>> grid(3, vector<int>(4, 0));   // 3×4 matrix of 0
v.pop_back();                // remove last
v.clear();

How can it grow? (The "doubling" trick)

A vector owns a block of memory with capacity C and uses size n ≤ C of it. On push_back: - if n < C: place at the end. O(1). - if n == C: allocate a new block of 2C, copy everything over, free the old. O(n) — expensive, but rare.

flowchart LR
  A["cap 1: [a]"] -->|push| B["cap 2: [a b]"] -->|push| C["cap 4: [a b c _]"] -->|push, push| D["cap 8..."]
Why doubling, not "add one slot"?

Adding one slot each time → copying 1+2+3+…+n ≈ n²/2 elements total. Doubling → copies 1+2+4+…+n/2 ≈ n total. So n pushes cost O(n) overall: amortised O(1) per push. (Amortised = averaged over many operations; one costly operation pays for lots of cheap ones, like paying rent monthly to avoid daily haggling.)

Consequence: after a push that reallocates, earlier pointers/iterators/references into the vector become invalid (the old block was freed). Don't hold them across push_back. If you know the final size, call v.reserve(n) first.

Handy: v.front(), v.back(), v.empty(), v.insert(v.begin()+i, x) (O(n): shifts everything), v.erase(v.begin()+i) (O(n)).

4.4 Putting it together: prefix sums (first real DSA idea)

Problem: many queries "what's the sum of a[l..r]?" Doing a loop each time costs O(n) per query.

Idea: precompute pre[i] = a[0] + … + a[i-1]. Then sum(l..r) = pre[r+1] − pre[l]. Why: the prefix up to r+1 contains everything up to r; subtracting the prefix before l removes the unwanted left part.

#include <iostream>
#include <vector>
using namespace std;
int main() {
    vector<int> a = {3, 1, 4, 1, 5, 9, 2, 6};
    int n = a.size();
    vector<long long> pre(n + 1, 0);
    for (int i = 0; i < n; ++i) pre[i + 1] = pre[i] + a[i];
    // sum of a[2..5] = 4+1+5+9 = 19
    cout << pre[6] - pre[2] << "\n";
}

Cost: O(n) once, then O(1) per query. This "pay once, answer fast" pattern recurs everywhere in DSA.

Module 5 — Pointers, references, and memory

Kid version

Every mailbox has a number (its address). A pointer is a variable whose value is another box's address — like a sticky note reading "the treasure is in box 1008". A pointer doesn't hold the treasure; it tells you where to look.

5.1 Pointers

int x = 10;
int *p = &x;     // & = "address of x".  p now holds x's address.
cout << p;       // 0x7ffe...   (an address)
cout << *p;      // 10          (* = "go to that address and look inside": dereference)
*p = 20;         // writes through the pointer
cout << x;       // 20 — x changed!

Memorise the two meanings of the symbols: | Where | & means | * means | |---|---|---| | in an expression | address-of | dereference (follow the arrow) | | in a declaration | "reference to" (int &r) | "pointer to" (int *p) |

Why do pointers exist? 1. Share data without copying (pass a huge object's address, not the object). 2. Build structures whose pieces point to each other — linked lists, trees, graphs. 3. Create memory at run time whose size you only know while running (§5.4).

nullptr = "points to nothing". Dereferencing it → crash (segmentation fault). Always check if it might be null.

5.2 Pointers and arrays are cousins

An array's name decays to a pointer to its first element: int a[5]; int *p = a; → p == &a[0].

Pointer arithmetic: p + 1 moves by one element (not one byte): the compiler adds sizeof(int) = 4 bytes. That's why a[i] ≡ *(a + i) — exactly the "start + i steps" rule from §4.1. (It even means i[a] compiles. Don't.)

int a[4] = {1,2,3,4};
for (int *p = a; p != a + 4; ++p) cout << *p << " ";
Arrays decay → `sizeof` lies in functions

void f(int a[]) { sizeof(a) } gives the size of a pointer (8), not the array. The function doesn't know the length — always pass the size too (or use vector).

5.3 References: a safer cousin

int &r = x; makes r a second name for x (no separate box; it is x). Must be initialised, can't be re-pointed, can't be null. Under the hood the compiler usually implements it as a pointer, but gives you nicer syntax and fewer ways to shoot yourself.

5.4 The two memory regions: stack vs heap

 high address ┌───────────────┐
              │     STACK     │  ← local variables, function frames. Auto-managed. Small (~8MB).
              │       ↓       │
              │               │
              │       ↑       │
              │     HEAP      │  ← memory YOU request with new. Big. YOU free it.
              ├───────────────┤
              │ globals/static│
              ├───────────────┤
              │  program code │
 low address  └───────────────┘

Stack: automatic. Allocation = move a marker. Fast. But everything dies when the function returns, and the size must be known at compile time.

Heap (free store): you ask the OS for memory with new, and it stays until you release it with delete. Slower (the allocator must find a free chunk), but flexible in size and lifetime.

int *p = new int(42);         // box on the heap holding 42
int *arr = new int[n];        // n ints (n decided at run time!)
// ... use them ...
delete p;                     // free ONE
delete[] arr;                 // free an ARRAY (note the [])

The four classic memory bugs (know them by name)

  1. Memory leak — you new but forget delete. The memory stays reserved until the program ends. A long-running server slowly eats all RAM and dies.
  2. Dangling pointer — you delete p then use *p. The box is no longer yours; it may hold anything now. (Setting p = nullptr after delete helps catch it.)
  3. Double free — delete p; delete p; corrupts the allocator's bookkeeping → crash.
  4. Returning address of a local —
int* bad() { int x = 5; return &x; }   // x dies at '}', pointer now dangles!

Why: x lived in bad's stack frame, which was discarded. The address still exists but the box has been recycled.

Why does C++ make *you* manage this?

A garbage collector (Java/Python) must pause to hunt for unused memory, and costs extra memory and unpredictability. C++ gives you control and predictable speed. Modern C++ fixes the danger without the cost by tying memory release to variable lifetime — RAII, covered in Module 6/8. In modern code you will rarely write raw new/delete; you'll use vector and smart pointers. But you must understand what they do for you.

5.5 Pointers to structs and the arrow

struct Node { int val; Node *next; };
Node *n = new Node{5, nullptr};
cout << (*n).val;   // clumsy
cout << n->val;     // `->` = "follow pointer, then take member"

This tiny Node is the seed of linked lists, trees and graphs (Parts II–IV).

Module 6 — Classes and Object-Oriented Programming

Kid version

A struct is a lunchbox that bundles different things (name, age, marks) into one object. A class is the same, plus rules: the box has built-in buttons (functions) and some compartments are locked from outsiders — so nobody can set your age to −5.

6.1 Structs and classes

struct Student { string name; int marks; };
Student s{"Asha", 91};
cout << s.name << s.marks;

class BankAccount {
private:                       // only the class's own functions can touch these
    long long balance = 0;
public:                        // anyone can use these
    void deposit(long long x) { if (x > 0) balance += x; }
    bool withdraw(long long x) {
        if (x <= 0 || x > balance) return false;
        balance -= x; return true;
    }
    long long get() const { return balance; }   // const: promises not to modify the object
};
Why hide data? (**Encapsulation**)

The class guarantees its own rules (invariants): "balance never goes negative." If balance were public, any code anywhere could break that, and finding the culprit means searching the whole program. With private data, only a handful of member functions can possibly be guilty. (struct and class are identical except struct defaults to public, class to private.)

6.2 Constructors and destructors — birth and death

#include <iostream>
using namespace std;
class Array {
    int n; int *data;
public:
    Array(int n_) : n(n_), data(new int[n_]()) {          // constructor: runs at birth
        cout << "born\n";
    }
    ~Array() { delete[] data; cout << "died\n"; }         // destructor: runs at death
};
int main() {
    Array a(5);        // "born"
}                      // "died"  ← automatically, when a goes out of scope
RAII — the most important C++ idea

Resource Acquisition Is Initialisation: acquire the resource (memory, file, lock) in the constructor; release it in the destructor. Since C++ guarantees destructors run when an object goes out of scope — even on early return or an exception — resources can never leak, without any garbage collector. vector, string, unique_ptr, ifstream, lock_guard all work this way.

The part after : in the constructor is the member initialiser list — it initialises members directly (rather than default-then-assign). Members are initialised in the order they're declared in the class, not the order in the list (a source of subtle bugs: if data's initialiser used n, but data were declared before n, it would read an uninitialised n. Keep the list in declaration order — -Wall warns you).

6.3 The copy problem, and the Rule of Three/Five

Array a(5);
Array b = a;     // default copy: copies the POINTER, not the data

Now a.data and b.data point to the same heap block. When both die, each calls delete[] on the same block → double free. The compiler's automatic copy is a shallow copy (copies members bit by bit). If you own a resource you need a deep copy:

Array(const Array& o) : n(o.n), data(new int[o.n]) {          // copy constructor
    for (int i = 0; i < n; ++i) data[i] = o.data[i];
}
Array& operator=(const Array& o) {                            // copy assignment
    if (this == &o) return *this;       // self-assignment guard
    int *nd = new int[o.n];
    for (int i = 0; i < o.n; ++i) nd[i] = o.data[i];
    delete[] data; data = nd; n = o.n;
    return *this;
}

Rule of Three: if you write a destructor, copy-constructor or copy-assignment, you almost certainly need all three. Rule of Five adds the move constructor/assignment (Module 8). Rule of Zero (best): own nothing raw — use vector/smart pointers and write none of them.

6.4 Inheritance and polymorphism

class Shape {
public:
    virtual double area() const = 0;     // pure virtual: no body → Shape is abstract
    virtual ~Shape() = default;          // virtual destructor (see below)
};
class Circle : public Shape {
    double r;
public:
    Circle(double r) : r(r) {}
    double area() const override { return 3.14159265 * r * r; }
};
class Rect : public Shape {
    double w, h;
public:
    Rect(double w, double h) : w(w), h(h) {}
    double area() const override { return w * h; }
};

Shape *s1 = new Circle(1), *s2 = new Rect(2, 3);
cout << s1->area() << " " << s2->area();   // each calls ITS OWN area()
How does `s1->area()` know to call Circle's version?

The compiler can't know at compile time what s1 really points to. Any class with a virtual function gets a hidden table, the vtable — an array of function pointers, one slot per virtual function — and every object carries a hidden pointer (vptr) to its class's vtable. A virtual call = follow the vptr, look up the slot, jump. Cost: one extra memory read. That is runtime polymorphism: one interface, many behaviours.

Why a virtual destructor? delete s1; through a Shape* must destroy a full Circle. Without virtual, only ~Shape runs — the Circle's part leaks (undefined behaviour). Rule: any base class meant for polymorphism gets a virtual destructor.

override makes the compiler verify you really override something (catches typos in the signature). Prefer composition ("has-a") over inheritance ("is-a") unless the "is-a" is truly natural.

6.5 Operator overloading and this

Inside a member function, this is a pointer to the object being operated on.

struct Vec2 {
    double x, y;
    Vec2 operator+(const Vec2& o) const { return {x + o.x, y + o.y}; }
    bool operator<(const Vec2& o) const { return tie(x, y) < tie(o.x, o.y); }
};
// Now Vec2 a, b; a + b works, and Vec2 can be a key in set/map or be sorted.

Why it matters in DSA: to put your own type in a set, map, priority_queue or sort, you must define how two values compare (operator< or a custom comparator).

Module 7 — Templates and the STL

7.1 Templates: write once for every type

mx(int,int) and mx(double,double) are the same logic. A template is a stencil; the compiler stamps out a real function for every type you use.

template <typename T>
T mx(T a, T b) { return a > b ? a : b; }
mx(3, 7); mx(2.5, 1.5); mx(string("a"), string("b"));

This happens at compile time — zero run-time cost. vector<int> and vector<string> are two different classes generated from one template. That is why the STL is both generic and fast.

7.2 The STL map

The Standard Template Library has three parts: containers (store things), iterators (walk over things), algorithms (do things). Because algorithms work through iterators, sort doesn't care whether it's sorting a vector or an array.

Iterators = generalised pointers

vector<int> v = {5, 2, 9};
for (auto it = v.begin(); it != v.end(); ++it) cout << *it;

begin() points to the first element; end() points one past the last (a "half-open" range [begin, end)). Why one past? An empty range is then begin == end (no special case), and the length is just end − begin.

Module 8 — Modern C++: smart pointers and move semantics

8.1 Smart pointers (RAII applied to new)

#include <memory>
auto p = make_unique<int>(42);        // sole owner. Freed automatically.
auto q = make_shared<int>(7);         // shared ownership with a reference count
auto r = q;                           // count = 2; freed when the LAST owner dies
  • unique_ptr: exactly one owner; can't be copied (only moved). Zero overhead. Default choice.
  • shared_ptr: reference-counted. Costs extra. Beware cycles (A owns B owns A → never freed; break with weak_ptr).

You now essentially never type delete.

8.2 Move semantics — "steal, don't copy"

Kid version

You're moving house. You could photocopy every book (copy) and shred the originals — absurd. Or you hand over the box of books (move). The old house is empty, the new house owns the books.

Returning or passing a big vector by value used to mean a deep copy. A move just steals the internal pointer and leaves the source empty:

vector<int> a(1000000, 1);
vector<int> b = move(a);   // b takes a's buffer: O(1). a is now empty (valid but unspecified)

move(x) doesn't move anything itself — it casts x to "you may steal from me" (an rvalue reference T&&). Types with a move constructor then take the resources. In practice: returning a local by value is fine (the compiler elides/moves it); push_back(move(obj)) avoids a copy; swap is cheap.

Module 9 — Complexity: measuring an algorithm without a stopwatch

Kid version

Two kids look for a name in a phone book. Kid A reads every page from the start. Kid B opens to the middle, decides "my name is in the first half", throws away the other half, and repeats. Who wins? And — the key question — what happens when the phone book becomes 1000× thicker? Complexity answers that second question. It measures how work grows with input size n, ignoring the speed of the computer.

9.1 Counting steps

Count the basic operations as a function of n:

for (int i = 0; i < n; ++i)              // n times → O(n)
    sum += a[i];
 
for (int i = 0; i < n; ++i)              // n × n = n² → O(n²)
    for (int j = 0; j < n; ++j) cnt++;
 
for (int i = 1; i < n; i *= 2) cnt++;     // doubles each time: runs log₂ n times → O(log n)

Big-O keeps only the dominant term and drops constants: 3n² + 100n + 7 → $O(n^2)$. Why drop constants? Because for huge n the biggest term swamps the rest, and constants depend on the machine, not the algorithm. Formal: $f(n)=O(g(n))$ if ∃ $c, n_0$: $f(n) \le c\,g(n)$ for all $n \ge n_0$.

9.2 Other notations, space, and amortised

  • $\Omega(g)$: lower bound ("at least"). $\Theta(g)$: tight ("exactly this growth"). Big-O is "at most".
  • Best / average / worst case. Quick-sort is O(n log n) on average, O(n²) in the worst case. Usually we quote the worst case (a guarantee).
  • Space complexity: extra memory used. Recursion depth counts (each frame costs memory).
  • Amortised: averaged over a sequence (e.g. push_back — Module 4).

Why log n so often? $\log_2 n$ = "how many times can I halve n before reaching 1?" Anything that halves the problem each step is O(log n): binary search, balanced trees, binary exponentiation. $\log_2(10^9)\approx 30$ — a billion becomes thirty.

The Master Theorem intuition (for divide-and-conquer $T(n)=aT(n/b)+f(n)$): compare the work at the leaves with the work at the root. Merge sort: $T(n)=2T(n/2)+n$: each of the $\log n$ levels does $n$ total work → $n\log n$.

Module 10 — Recursion and backtracking

Kid version

"How many people are in the line ahead of me?" — you can't see the front, so you ask the person ahead: "How many are ahead of you?" They ask the next… until the first person says "0". Then each person adds 1 as the answers come back down the line. Recursion = solve a problem by asking a smaller copy of the same problem, and a base case that stops it.

Every recursive function has: (1) base case — answer known directly; (2) recursive case — reduce to a smaller problem and trust it works (the leap of faith — this is induction).

long long fact(int n) {
    if (n <= 1) return 1;        // base case
    return n * fact(n - 1);      // smaller problem
}

Trace fact(3): calls fact(2) → calls fact(1) returns 1 → fact(2) returns 2 → fact(3) returns 6. The call stack (Module 3) holds the waiting frames. Without a base case: stack overflow.

10.1 Fibonacci — and why naive recursion is a disaster

int fib(int n) { return n < 2 ? n : fib(n-1) + fib(n-2); }

fib(5) recomputes fib(3) twice, fib(2) three times… The call tree doubles: O(2ⁿ) (≈1.6ⁿ). fib(50) would take hours. The cure — remembering answers — is dynamic programming (Module 16): memoisation turns it into O(n).

10.2 Fast exponentiation (binary exponentiation)

Compute $x^n$ with $O(\log n)$ multiplications: $x^n = (x^{n/2})^2$ if n even; $x \cdot x^{n-1}$ if odd. Why it works: squaring halves the exponent each time.

long long power(long long x, long long n, long long mod) {
    long long r = 1; x %= mod;
    while (n > 0) {
        if (n & 1) r = r * x % mod;   // this bit of n is set → include x^(2^k)
        x = x * x % mod;              // x, x², x⁴, x⁸ …
        n >>= 1;
    }
    return r;
}

Binary view: $x^{13}=x^{8}\cdot x^{4}\cdot x^{1}$ because 13 = 1101₂. 1e9+7 as mod keeps numbers inside long long (since $(10^9)^2 = 10^{18} < 9.2\times 10^{18}$).

10.3 Backtracking — exploring choices

Idea: build an answer one choice at a time; if a choice leads to a dead end, undo it and try the next. It's a depth-first walk through a tree of decisions.

Generate all subsets (each element: take it or skip it → 2ⁿ):

using namespace std;
vector<int> cur;

    if (i == (int)a.size()) {                // decided about every element
        for (int x : cur) cout << x << " ";
        cout << "\n"; return;
    }
    subsets(a, i + 1);                       // choice 1: skip a[i]
    cur.push_back(a[i]);                     // choice 2: take a[i]
    subsets(a, i + 1);
    cur.pop_back();                          // UNDO — the heart of backtracking
}
int main() { vector<int> a = {1, 2, 3}; subsets(a, 0); }

Permutations, N-Queens (place a queen per row; prune any column/diagonal conflict), Sudoku use the same shape: choose → recurse → un-choose. Pruning = abandoning a branch early when it can't succeed — it's what makes backtracking feasible.

#include <iostream>
using namespace std;
// N-Queens: count solutions. cols / diagonals tracked in boolean arrays.
int n, cnt;
bool col[20], d1[40], d2[40];
void place(int r) {
    if (r == n) { ++cnt; return; }
    for (int c = 0; c < n; ++c) {
        if (col[c] || d1[r + c] || d2[r - c + n]) continue;  // attacked → prune
        col[c] = d1[r + c] = d2[r - c + n] = true;           // choose
        place(r + 1);                                        // recurse
        col[c] = d1[r + c] = d2[r - c + n] = false;          // un-choose
    }
}
int main() { n = 8; place(0); cout << cnt; }   // 92

Why d1 = r+c and d2 = r−c? Every cell on the same "/" diagonal has equal r+c; on the same "\" diagonal, equal r−c.

11.1 Binary search — the art of halving

Kid version

"I'm thinking of a number from 1 to 1000." You guess 500: "higher." Now 501–1000. Guess 750: "lower." Every guess throws away half the possibilities. Ten guesses are enough ($2^{10}=1024$).

Requirement: the data must be sorted (or, more generally, the question must be monotonic: false…false true…true). Why: the whole trick is "if the middle is too small, everything to its left is too small too" — that's what lets us discard half without looking.

// index of x in sorted a, or -1.  Invariant: if x exists, it lies in [lo, hi]
int bsearch(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;      // NOT (lo+hi)/2 : that can overflow int!
        if (a[mid] == x) return mid;
        if (a[mid] < x) lo = mid + 1;      // x is right of mid
        else            hi = mid - 1;      // x is left of mid
    }
    return -1;
}

Most bugs come from the boundaries (< vs <=, mid+1 vs mid). Fix by choosing an invariant and sticking to it. The most reusable form finds the first index where a predicate is true:

// first i in [0, n] with ok(i) true, assuming ok is false...false true...true
int lo = 0, hi = n;                 // answer may be n ("none true")
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (ok(mid)) hi = mid;          // mid could be the answer → keep it
    else         lo = mid + 1;      // mid is false → answer is further right
}
// lo == hi == the first true

This is exactly lower_bound.

Binary search on the answer

Powerful trick: when you can't search an array but can test a candidate answer, and "feasible" is monotonic, binary-search the answer itself.

Problem: split an array into at most k parts to minimise the largest part-sum. Guess a limit L; greedily check if k parts suffice (O(n)). Larger L is always at least as feasible → monotonic. Binary search L in [max element, total sum]: O(n log(sum)).

bool feasible(const vector<int>& a, int k, long long L) {
    int parts = 1; long long cur = 0;
    for (int x : a) {
        if (cur + x > L) { ++parts; cur = 0; }
        cur += x;
    }
    return parts <= k;
}
// lo = max(a), hi = sum(a); find smallest L with feasible(L)

11.2 Sorting — the algorithms and why they cost what they cost

Why study them when std::sort exists? Because each embodies a technique (incremental, divide-and-conquer, heaps, counting) you'll reuse everywhere, and interviewers love them.

Bubble / selection / insertion — O(n²)

  • Selection: find the minimum, put it first; repeat on the rest. Always n²/2 comparisons.
  • Insertion: keep the left part sorted; take the next card and slide it into place (like sorting a hand of cards). O(n) if nearly sorted — that's why real libraries use it for small chunks.
  • Bubble: repeatedly swap adjacent out-of-order pairs; large values "bubble" to the end. Never use in practice.
void insertionSort(vector<int>& a) {
    for (int i = 1; i < (int)a.size(); ++i) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; --j; }   // shift bigger ones right
        a[j + 1] = key;
    }
}

Why n²? Each element may travel past up to n others; each swap removes exactly one inversion (out-of-order pair), and a reversed array has n(n−1)/2 inversions. Any sort that only swaps adjacent elements needs ≥ #inversions steps.

Merge sort — O(n log n), stable

Idea (divide & conquer): split in half, sort each half recursively, merge the two sorted halves (walk both with two fingers, always taking the smaller front). Merging is O(n) since each element is taken once.

void mergeSort(vector<int>& a, int l, int r) {       // sorts a[l, r)
    if (r - l < 2) return;
    int m = (l + r) / 2;
    mergeSort(a, l, m); mergeSort(a, m, r);
    vector<int> t; t.reserve(r - l);
    int i = l, j = m;
    while (i < m && j < r) t.push_back(a[i] <= a[j] ? a[i++] : a[j++]);  // <= keeps it stable
    while (i < m) t.push_back(a[i++]);
    while (j < r) t.push_back(a[j++]);
    copy(t.begin(), t.end(), a.begin() + l);
}

Levels: log₂n (halving). Work per level: n (merging). Total n log n — always, no bad case. Cost: O(n) extra memory. Stable = equal elements keep their original relative order (matters when sorting records by one field after another).

Why can't any comparison sort beat n log n? A sort must distinguish among n! possible orderings; each comparison is a yes/no answer, so a decision tree with n! leaves has depth ≥ $\log_2(n!) \approx n\log_2 n$. This is a lower bound — it's a fact about the problem, not about our cleverness. (Counting sort escapes it by not comparing.)

Bonus: merge sort counts inversions in O(n log n) — while merging, whenever you take from the right half, every remaining left element forms an inversion with it.

Quick sort — average O(n log n), in-place, fastest in practice

Idea: pick a pivot; partition so smaller elements go left, larger right; the pivot is now in its final place; recurse on both sides.

int partition(vector<int>& a, int lo, int hi) {         // Lomuto scheme
    int pivot = a[hi], i = lo;
    for (int j = lo; j < hi; ++j) if (a[j] < pivot) swap(a[i++], a[j]);
    swap(a[i], a[hi]);
    return i;
}
void quickSort(vector<int>& a, int lo, int hi) {
    if (lo >= hi) return;
    int p = partition(a, lo, hi);
    quickSort(a, lo, p - 1); quickSort(a, p + 1, hi);
}

Good pivots split evenly → depth log n → n log n. A bad pivot (always the smallest) → depth n → O(n²) (e.g. fixed last-element pivot on already-sorted data). Fix: random pivot (swap(a[hi], a[lo + rand()%(hi-lo+1)])), making the bad case astronomically unlikely. std::sort uses introsort: quicksort that switches to heapsort if recursion gets too deep, and insertion sort for tiny ranges.

Quickselect — find the k-th smallest in O(n) average: partition, then recurse into only the side containing k. (nth_element does it.)

Heap sort — O(n log n), in-place

Build a max-heap (Module 13), then repeatedly swap the max to the end. Guaranteed n log n, O(1) extra space, not stable, poor cache behaviour.

Counting sort & radix sort — O(n + k): beating the bound

If keys are small integers 0..k, don't compare — count how many of each, then write them out:

vector<int> cnt(k + 1, 0);
for (int x : a) cnt[x]++;
int idx = 0;
for (int v = 0; v <= k; ++v) while (cnt[v]--) a[idx++] = v;

Radix sort applies a stable counting sort digit by digit.

12.1 Linked list — a chain of nodes

Kid version

A scavenger hunt: each clue tells you where the next clue is hidden. To reach clue #50 you must follow 49 clues in order. But inserting a new clue between two is easy — just rewrite one note.

struct Node { int val; Node* next; Node(int v) : val(v), next(nullptr) {} };

Array vs linked list — the trade-off flows from how memory is laid out:

array / vector linked list
layout contiguous scattered nodes joined by pointers
access i-th O(1) O(i) (must walk)
insert/erase in the middle (given the spot) O(n) (shift) O(1) (re-link)
cache friendliness excellent poor
extra memory none one pointer per node

In practice vectors beat lists in speed almost always (cache!). But linked lists teach pointer manipulation, and the idea underlies trees, graphs, hash chains, LRU caches.

#include <bits/stdc++.h>
using namespace std;
struct Node { int val; Node* next; Node(int v) : val(v), next(nullptr) {} };
 
Node* pushFront(Node* head, int v) { Node* n = new Node(v); n->next = head; return n; }
 
Node* reverseList(Node* head) {
    Node *prev = nullptr, *cur = head;
    while (cur) {
        Node* nxt = cur->next;   // 1. remember the rest
        cur->next = prev;        // 2. flip this arrow
        prev = cur;              // 3. advance prev
        cur = nxt;               // 4. advance cur
    }
    return prev;                 // new head
}
void print(Node* h) { for (; h; h = h->next) cout << h->val << " "; cout << "\n"; }
void freeList(Node* h) { while (h) { Node* t = h->next; delete h; h = t; } }
 
int main() {
    Node* h = nullptr;
    for (int i = 5; i >= 1; --i) h = pushFront(h, i);   // 1 2 3 4 5
    print(h);
    h = reverseList(h);                                  // 5 4 3 2 1
    print(h);
    freeList(h);
}

Why save nxt first? Flipping cur->next destroys the only link to the rest of the list — you'd lose it. Draw the arrows on paper; every pointer problem is solved by drawing and by ordering the updates so nothing is lost.

Fast & slow pointers (Floyd's tortoise and hare) - Middle: slow moves 1, fast moves 2; when fast hits the end, slow is in the middle. - Cycle detection: if there's a loop, fast eventually laps slow and they meet (the gap shrinks by 1 each step, so it must hit 0). No loop → fast reaches null.

bool hasCycle(Node* h) {
    Node *s = h, *f = h;
    while (f && f->next) { s = s->next; f = f->next->next; if (s == f) return true; }
    return false;
}

Doubly linked list adds prev; O(1) deletion given a node. std::list is one.

12.2 Stack — Last In, First Out

Kid version: a stack of plates. You add and remove only at the top.

Operations (all O(1)): push, pop, top, empty. It arises whenever things nest: function calls, undo, matching brackets, expression parsing, DFS.

bool balanced(const string& s) {
    stack<char> st;
    for (char c : s) {
        if (c == '(' || c == '[' || c == '{') st.push(c);
        else {
            if (st.empty()) return false;
            char o = st.top(); st.pop();
            if ((c==')' && o!='(') || (c==']' && o!='[') || (c=='}' && o!='{')) return false;
        }
    }
    return st.empty();
}

Why a stack? The most recently opened bracket must be the first one closed — LIFO exactly.

Monotonic stack — "next greater element" in O(n)

For each element find the next element to the right that is larger. Naive: O(n²). Keep a stack of indices whose answer is still unknown; their values are decreasing. When a bigger value arrives, it is the answer for every smaller element on top.

vector<int> nextGreater(const vector<int>& a) {
    int n = a.size(); vector<int> res(n, -1); stack<int> st;
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && a[st.top()] < a[i]) { res[st.top()] = a[i]; st.pop(); }
        st.push(i);
    }
    return res;
}

Why O(n)? Each index is pushed once and popped at most once → ≤ 2n operations total, even though there's a while inside a for. (Always count total work, not loop nesting.) This pattern solves "largest rectangle in histogram", "daily temperatures", "stock span".

12.3 Queue and deque

Queue — First In, First Out (a line at a ticket counter): push at back, pop from front. Used in BFS, scheduling, buffering. deque supports O(1) at both ends.

Monotonic deque — sliding window maximum in O(n): keep indices in the deque with decreasing values; the front is always the current window's max; drop from the back anything smaller than the new element (it can never be a maximum while the newer, larger one is in the window), and drop from the front when it leaves the window.

vector<int> slidingMax(const vector<int>& a, int k) {
    deque<int> dq; vector<int> res;
    for (int i = 0; i < (int)a.size(); ++i) {
        while (!dq.empty() && a[dq.back()] <= a[i]) dq.pop_back();
        dq.push_back(i);
        if (dq.front() <= i - k) dq.pop_front();
        if (i >= k - 1) res.push_back(a[dq.front()]);
    }
    return res;
}

12.4 Two pointers and sliding window

Instead of two nested loops (n²), move two indices monotonically (n). - Sorted array, pair with sum S: l=0, r=n-1; if sum too small, ++l (only a bigger left helps); too big, --r. Why correct: the discarded element can't be part of any valid pair with the remaining ones. - Longest substring without repeated characters: window [l, r]; extend r; on a repeat, advance l until valid. Each pointer moves ≤ n times → O(n).

13.1 Hash tables

Kid version

A school with 100 lockers. To store your bag, don't search for an empty locker: compute locker = (your roll number) mod 100. To find it later, compute the same thing. No searching! Problem: two kids can map to the same locker — a collision.

A hash function maps a key to an index h(key) mod m. Lookup/insert are O(1) on average because you jump straight to the slot.

Collision strategies: - Chaining: each slot holds a linked list/vector of entries. - Open addressing: if the slot is taken, probe the next (linear probing) until a free one.

Keep the load factor (items/slots) small; when too full, rehash into a bigger table (the doubling trick again → amortised O(1)).

// A tiny hash set of ints with chaining
struct HashSet {
    vector<vector<int>> b;
    HashSet(int m = 1009) : b(m) {}
    int h(int x) const { return ((x % (int)b.size()) + b.size()) % b.size(); }
    bool has(int x) { for (int y : b[h(x)]) if (y == x) return true; return false; }
    void add(int x) { if (!has(x)) b[h(x)].push_back(x); }
};

Why m is often prime: if keys share a common factor with m (like multiples of 10 with m=100), they'd land in few buckets. A prime modulus spreads patterns evenly.

Classic uses: two-sum (store seen values; look up target − x), counting frequencies, detecting duplicates, grouping anagrams (key = sorted string), prefix-sum + hash map for "number of subarrays with sum K" (count how many earlier prefix sums equal current − K).

long long subarraysWithSum(const vector<int>& a, long long K) {
    unordered_map<long long,int> seen; seen[0] = 1;
    long long pre = 0, ans = 0;
    for (int x : a) { pre += x; ans += seen[pre - K]; seen[pre]++; }
    return ans;
}

Why it works: sum(l..r) = pre[r] − pre[l−1] = K ⇔ pre[l−1] = pre[r] − K.

`unordered_map` anti-hack: use a custom hash with a random seed (e.g. `splitmix64` + `chrono` time), or use `map` when O(log n) is fine.

13.2 Heap / priority queue

Kid version

A hospital emergency room. Patients are served by urgency, not arrival. You always want "who's most urgent?" quickly — and new patients keep arriving.

A binary heap is a complete binary tree (all levels full except possibly the last, filled left to right) with the heap property: every parent ≥ its children (max-heap). The max is at the root — O(1) to read.

Magic: store the tree in an array — no pointers! For 0-indexed node i: parent (i−1)/2, children 2i+1, 2i+2. Why can we? "Complete" means no gaps, so the shape is implied by the count.

index: 0  1  2  3  4  5
value: 9  7  8  3  5  2         9
                              /   \
                             7     8
                            / \   /
                           3   5 2
  • push: put at the end, sift up (swap with parent while bigger). Height log n → O(log n).
  • pop max: move the last element to the root, sift down (swap with the larger child while smaller). O(log n).
  • build from n elements: sift down from the last parent upward — O(n), not n log n (most nodes are near the bottom and travel little).
struct MaxHeap {
    vector<int> a;
    void push(int x) {
        a.push_back(x);
        int i = a.size() - 1;
        while (i > 0 && a[(i - 1) / 2] < a[i]) { swap(a[(i - 1) / 2], a[i]); i = (i - 1) / 2; }
    }
    int pop() {
        int top = a[0]; a[0] = a.back(); a.pop_back();
        int i = 0, n = a.size();
        while (true) {
            int l = 2 * i + 1, r = l + 1, big = i;
            if (l < n && a[l] > a[big]) big = l;
            if (r < n && a[r] > a[big]) big = r;
            if (big == i) break;
            swap(a[i], a[big]); i = big;
        }
        return top;
    }
};

Uses: k largest elements (keep a min-heap of size k), merging k sorted lists, Dijkstra, scheduling, running median (two heaps), Huffman coding.

14.1 Traversals — and why they're recursive

A tree is self-similar: each child is itself a smaller tree. So recursion is natural.

void inorder(TreeNode* t)   { if(!t)return; inorder(t->left);  visit(t); inorder(t->right); }  // L N R
void preorder(TreeNode* t)  { if(!t)return; visit(t); preorder(t->left); preorder(t->right); } // N L R
void postorder(TreeNode* t) { if(!t)return; postorder(t->left); postorder(t->right); visit(t);} // L R N
  • Preorder — copy a tree / serialise (parent before children).
  • Postorder — delete a tree / compute heights, sizes (children first).
  • Level order (BFS) — use a queue: process a node, push its children.
int height(TreeNode* t) { return t ? 1 + max(height(t->left), height(t->right)) : 0; }

Trees by recursion — the template: answer for a node = combine(answer(left), answer(right), node's own value). Diameter, max path sum, lowest common ancestor, "is balanced" all follow it. Each node visited once → O(n).

14.2 Binary Search Tree (BST)

Rule: for every node, everything in the left subtree is smaller, everything in the right is larger.

Why this is clever: searching is like binary search — at each node, one comparison discards a whole subtree. Inorder traversal of a BST visits keys in sorted order (a great test of whether a tree is a BST).

TreeNode* insert(TreeNode* t, int x) {
    if (!t) return new TreeNode(x);
    if (x < t->val) t->left  = insert(t->left, x);
    else if (x > t->val) t->right = insert(t->right, x);
    return t;
}
bool find(TreeNode* t, int x) {
    while (t) { if (x == t->val) return true; t = (x < t->val) ? t->left : t->right; }
    return false;
}

Cost is O(height). Random inserts → height ≈ log n (great). Sorted inserts → a chain, height n (degenerates into a linked list!). Cure: self-balancing trees (AVL: heights of siblings differ by ≤1, repaired with rotations; red-black trees: looser colour rules). std::set / std::map are red-black trees, so they guarantee O(log n).

Deletion: leaf → remove; one child → replace by it; two children → replace its value with the inorder successor (smallest in the right subtree), then delete that node.

14.3 Trie (prefix tree)

Each edge is a character; a path from the root spells a prefix. Lookup of a word of length L costs O(L), independent of how many words are stored.

struct Trie {
    struct N { int nx[26]; bool end = false; N() { fill(nx, nx + 26, -1); } };
    vector<N> t{N()};
    void add(const string& s) {
        int u = 0;
        for (char ch : s) {
            int c = ch - 'a';
            if (t[u].nx[c] < 0) { t[u].nx[c] = t.size(); t.push_back(N()); }
            u = t[u].nx[c];
        }
        t[u].end = true;
    }
    bool has(const string& s) {
        int u = 0;
        for (char ch : s) { u = t[u].nx[ch - 'a']; if (u < 0) return false; }
        return t[u].end;
    }
};

Use: autocomplete, spell check, longest common prefix, XOR-maximum (binary trie).

14.4 Range queries: Fenwick tree and segment tree

Problem: array with updates (change a[i]) and range-sum queries. Prefix sums give O(1) queries but O(n) updates. We want both fast: O(log n).

Fenwick tree (Binary Indexed Tree)

Idea: store partial sums so that any prefix is covered by ≤ log n blocks, each block's length being the lowest set bit of its index. i & -i isolates that bit (two's complement! -i flips all bits and adds 1, so only the lowest set bit survives the AND).

struct BIT {
    int n; vector<long long> t;
    BIT(int n) : n(n), t(n + 1, 0) {}
    void add(int i, long long v) { for (++i; i <= n; i += i & -i) t[i] += v; }   // 0-indexed API
    long long sum(int i) { long long s = 0; for (++i; i > 0; i -= i & -i) s += t[i]; return s; } // a[0..i]
    long long range(int l, int r) { return sum(r) - (l ? sum(l - 1) : 0); }
};

t[i] stores the sum of the lowbit(i) elements ending at i. Going down (i -= lowbit) strips blocks from a prefix; going up (i += lowbit) visits every block that contains position i.

Segment tree

A binary tree where each node stores an aggregate (sum / min / max / gcd) of a segment; the root covers [0, n−1], children cover the halves. Query decomposes [l, r] into O(log n) full nodes.

struct Seg {                       // iterative, bottom-up, point update, range sum [l, r)
    int n; vector<long long> t;
    Seg(int n) : n(n), t(2 * n, 0) {}
    void set(int i, long long v) { for (t[i += n] = v; i > 1; i >>= 1) t[i >> 1] = t[i] + t[i ^ 1]; }
    long long query(int l, int r) {
        long long s = 0;
        for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
            if (l & 1) s += t[l++];
            if (r & 1) s += t[--r];
        }
        return s;
    }
};

With lazy propagation it also does range updates in O(log n). Change + to min/max for other queries.

15.2 BFS — explore in rings (shortest path in unweighted graphs)

Throw a pebble into a pond: ripples spread outward one ring at a time. BFS visits all nodes at distance 1, then 2, then 3… using a queue (FIFO preserves the ring order).

#include <bits/stdc++.h>
using namespace std;
int main() {
    int n = 6;
    vector<vector<int>> adj(n);
    auto e = [&](int u, int v){ adj[u].push_back(v); adj[v].push_back(u); };
    e(0,1); e(0,2); e(1,3); e(2,3); e(3,4); e(4,5);
    vector<int> dist(n, -1); queue<int> q;
    dist[0] = 0; q.push(0);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : adj[u]) if (dist[v] < 0) { dist[v] = dist[u] + 1; q.push(v); }
    }
    for (int i = 0; i < n; ++i) cout << "dist[" << i << "]=" << dist[i] << "\n";
}

Why is BFS distance the shortest? Nodes leave the queue in non-decreasing distance order (induction on rings), and a node is first discovered from a node of the previous ring — so its first-found distance is minimal. Mark visited when you push, not when you pop, otherwise nodes get queued many times. Cost O(V+E) — each vertex enqueued once, each edge looked at once (twice if undirected).

Grid problems are graphs too: cells are nodes, 4 neighbours are edges (dx[] = {1,-1,0,0}, dy[] = {0,0,1,-1}).

15.3 DFS — go deep, then back up

DFS follows one path as far as it goes, then backtracks (the call stack is the stack). Like exploring a maze with chalk: mark where you've been, retrace on dead ends.

vector<vector<int>> adj; vector<char> vis;
void dfs(int u) {
    vis[u] = 1;
    for (int v : adj[u]) if (!vis[v]) dfs(v);
}

Uses: connected components (call dfs from every unvisited node, count calls), cycle detection, topological sort, bridges/articulation points, SCCs, flood fill. Recursion depth can reach V (10⁵–10⁶ → stack overflow!) — use an explicit stack for huge inputs.

Cycle detection in a directed graph — three colours: white (unseen), gray (on the current recursion path), black (finished). An edge to a gray node closes a cycle.

15.4 Topological sort (ordering with prerequisites)

For a DAG (directed acyclic graph), order vertices so every edge u→v has u before v — e.g. course prerequisites. Kahn's algorithm: repeatedly take a node with in-degree 0 (nothing blocks it), output it, and decrease its neighbours' in-degrees. If you output fewer than V nodes, a cycle exists (the cycle's nodes never reach in-degree 0).

vector<int> topo(int n, const vector<vector<int>>& adj) {
    vector<int> indeg(n, 0), order;
    for (int u = 0; u < n; ++u) for (int v : adj[u]) indeg[v]++;
    queue<int> q;
    for (int i = 0; i < n; ++i) if (!indeg[i]) q.push(i);
    while (!q.empty()) {
        int u = q.front(); q.pop(); order.push_back(u);
        for (int v : adj[u]) if (--indeg[v] == 0) q.push(v);
    }
    return order;     // size < n ⇒ cycle
}

15.5 Shortest paths with weights

Dijkstra (non-negative weights)

Idea: like BFS but "rings" by distance. Always finalise the unfinalised node with the smallest known distance — a min-heap gives it quickly. Why correct: when u has the smallest tentative distance, any other route to u must pass through some not-yet-finalised node whose distance is already ≥ d[u], and weights are ≥ 0, so it can't be shorter. Negative edges break exactly this argument.

vector<long long> dijkstra(int src, const vector<vector<pair<int,int>>>& adj) {
    const long long INF = LLONG_MAX / 4;
    vector<long long> d(adj.size(), INF);
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
    d[src] = 0; pq.push({0, src});
    while (!pq.empty()) {
        auto [du, u] = pq.top(); pq.pop();
        if (du > d[u]) continue;                 // stale entry: a better one was already processed
        for (auto [v, w] : adj[u])
            if (d[u] + w < d[v]) { d[v] = d[u] + w; pq.push({d[v], v}); }   // relax
    }
    return d;
}

Complexity: O((V+E) log V). Relaxation = "can going through u improve v?" — the core move of every shortest-path algorithm.

Bellman–Ford (handles negative weights): relax all edges V−1 times, O(VE). Why V−1? A shortest path has ≤ V−1 edges, and round k fixes paths with k edges. If round V still improves something → a negative cycle.

Floyd–Warshall (all pairs): O(V³), three lines:

for (int k = 0; k < n; ++k) for (int i = 0; i < n; ++i) for (int j = 0; j < n; ++j)
    d[i][j] = min(d[i][j], d[i][k] + d[k][j]);   // allow k as an intermediate stop

(k must be the outermost loop — it's the DP stage: "paths using only the first k vertices as stops".)

15.6 Disjoint Set Union (Union-Find) and MST

DSU tracks groups: find(x) = group leader, unite(a,b) = merge groups. Each group is a tree; the root is the leader. Two tricks make it nearly O(1): path compression (point everyone you pass straight at the root) and union by size (hang the smaller tree under the bigger).

struct DSU {
    vector<int> p, sz;
    DSU(int n) : p(n), sz(n, 1) { iota(p.begin(), p.end(), 0); }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (sz[a] < sz[b]) swap(a, b);
        p[b] = a; sz[a] += sz[b]; return true;
    }
};

Cost: O(α(n)) per operation, α = inverse Ackermann ≤ 4 for any n you'll ever meet.

Minimum Spanning Tree (connect all nodes with least total edge weight; V−1 edges, no cycle). Kruskal: sort edges by weight; take an edge if it connects two different groups (DSU). Why greedy works (cut property): for any split of the nodes in two sets, the cheapest edge crossing the split belongs to some MST.

long long kruskal(int n, vector<array<int,3>>& edges) {        // {w, u, v}
    sort(edges.begin(), edges.end());
    DSU d(n); long long total = 0;
    for (auto [w, u, v] : edges) if (d.unite(u, v)) total += w;
    return total;
}

Prim: grow one tree, always adding the cheapest edge leaving it (like Dijkstra with a heap).

Module 16 — Dynamic Programming (DP)

Kid version

You're climbing stairs, 1 or 2 steps at a time. "How many ways to reach step 10?" You don't want to recount from scratch every time. Notice: to land on step 10 you came from step 9 or step 8. So ways(10) = ways(9) + ways(8). Write each answer on a sticky note the first time you work it out, and reuse it. That's DP.

DP applies when a problem has: 1. Overlapping subproblems — the same smaller question is asked again and again (naive Fibonacci recomputing fib(3)). 2. Optimal substructure — the best answer is built from best answers to smaller pieces.

Recipe (follow it every time): 1. State: what small set of numbers describes a subproblem? (dp[i] = answer for the first i items…) 2. Transition: how does a state's answer follow from smaller states? 3. Base cases: the tiniest states answered directly. 4. Order: compute so that dependencies are ready (or use recursion + memo). 5. Answer: which state(s) hold the final answer?

16.1 Top-down (memoisation) vs bottom-up (tabulation)

// top-down: recursion + cache
long long memo[100];
long long fib(int n) {
    if (n < 2) return n;
    if (memo[n]) return memo[n];
    return memo[n] = fib(n - 1) + fib(n - 2);
}
// bottom-up: fill a table in order
long long fibTab(int n) {
    vector<long long> f(n + 2); f[0] = 0; f[1] = 1;
    for (int i = 2; i <= n; ++i) f[i] = f[i - 1] + f[i - 2];
    return f[n];
}

Why O(n)? There are n distinct states, each computed once with O(1) work. Complexity of DP = (#states) × (work per transition). Memoisation computes only needed states and is easier to write; tabulation avoids recursion depth and is usually faster. Space optimisation: fib needs only the last two values → O(1) space.

16.2 Classic 1-D problems

Climbing stairs / coin ways / min coins

Minimum coins to make amount A with coin values c[] (unlimited supply): - State: dp[x] = fewest coins for amount x. - Transition: dp[x] = 1 + min over coins c of dp[x − c] (the last coin used was c). - Base: dp[0] = 0; unreachable = ∞.

#include <bits/stdc++.h>
using namespace std;
int main() {
    vector<int> coins = {1, 5, 6, 9};
    int A = 11, INF = 1e9;
    vector<int> dp(A + 1, INF); dp[0] = 0;
    for (int x = 1; x <= A; ++x)
        for (int c : coins)
            if (x >= c && dp[x - c] + 1 < dp[x]) dp[x] = dp[x - c] + 1;
    cout << dp[A] << "\n";   // 2  (5 + 6)
}
Why does greedy fail here?

Greedy "take the largest coin ≤ remaining" gives 9+1+1 = 3 coins. DP tries all last-coin choices and so finds 5+6 = 2. Greedy works only when you can prove a local choice is safe (Module 17).

Longest Increasing Subsequence (LIS)

  • O(n²): dp[i] = 1 + max dp[j] for j<i with a[j]<a[i].
  • O(n log n): keep tails[k] = smallest possible tail of an increasing subsequence of length k+1. tails is always sorted, so binary-search where each new element belongs (replace the first tail ≥ x).
int lis(const vector<int>& a) {
    vector<int> t;
    for (int x : a) {
        auto it = lower_bound(t.begin(), t.end(), x);   // strictly increasing
        if (it == t.end()) t.push_back(x); else *it = x;
    }
    return t.size();
}

(tails is not the subsequence itself, only its length is meaningful.)

Maximum subarray sum (Kadane)

best ending at i = max(a[i], best ending at i−1 + a[i]) — either start fresh or extend; a negative running sum can only hurt, so drop it.

long long kadane(const vector<int>& a) {
    long long cur = a[0], best = a[0];
    for (size_t i = 1; i < a.size(); ++i) { cur = max<long long>(a[i], cur + a[i]); best = max(best, cur); }
    return best;
}

16.3 Two-dimensional DP

0/1 Knapsack

n items with weight w[i] and value v[i]; capacity W; each item used at most once; maximise value. - State: dp[i][c] = best value using the first i items with capacity c. - Transition: skip item i → dp[i−1][c]; take it → dp[i−1][c−w[i]] + v[i] (if fits). Take the max.

vector<int> dp(W + 1, 0);
for (int i = 0; i < n; ++i)
    for (int c = W; c >= w[i]; --c)               // BACKWARDS!
        dp[c] = max(dp[c], dp[c - w[i]] + v[i]);
Why loop `c` downward in the 1-D version?

dp[c − w[i]] must still hold the previous item's row. Going downward, smaller capacities haven't been overwritten yet. Going upward would reuse the item multiple times — which is actually the unbounded knapsack (and exactly how the coin-change loop above works).

Longest Common Subsequence (LCS) and Edit Distance

LCS of strings a, b: dp[i][j] = LCS of the first i chars of a and first j of b. - If a[i−1]==b[j−1]: dp[i][j] = dp[i−1][j−1] + 1 (match them). - Else dp[i][j] = max(dp[i−1][j], dp[i][j−1]) (drop one char from either).

int lcs(const string& a, const string& b) {
    int n = a.size(), m = b.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= m; ++j)
            dp[i][j] = (a[i-1] == b[j-1]) ? dp[i-1][j-1] + 1 : max(dp[i-1][j], dp[i][j-1]);
    return dp[n][m];
}

Edit distance (min insert/delete/replace to turn a into b): same table; dp[i][0]=i, dp[0][j]=j; match → dp[i−1][j−1]; else 1 + min(dp[i−1][j] (delete), dp[i][j−1] (insert), dp[i−1][j−1] (replace)).

Grid paths

dp[i][j] = dp[i−1][j] + dp[i][j−1] (arrive from above or from the left); with obstacles set blocked cells to 0.

16.4 Other DP shapes (know they exist)

  • Interval DP: dp[l][r] over substrings/segments (matrix-chain multiplication, burst balloons, palindrome partitioning). Iterate by increasing length.
  • Bitmask DP: dp[mask][last] for n ≤ 20 (travelling salesman in O(2ⁿ·n²)). A bitmask is a subset stored as an integer.
  • Digit DP: count numbers ≤ N with a property, building digit by digit.
  • DP on trees: dp[v] from children (max independent set, subtree sizes).
  • DP on DAGs / shortest paths: Floyd–Warshall and Bellman–Ford are DP.
How to *find* the state

Ask: "If I were standing in the middle of building the answer, what's the minimum information I need to know to continue, ignoring how I got here?" That information is the state. Too much → too many states; too little → wrong answers.

Module 17 — Greedy, bits, math and strings

17.1 Greedy algorithms

Greedy = at each step, take the choice that looks best right now, never reconsider. It's fast and simple — and only valid when you can prove it. Two standard proofs: exchange argument (swap any optimal solution toward the greedy choice without making it worse) and "greedy stays ahead".

Interval scheduling — pick the max number of non-overlapping meetings. Greedy: sort by earliest finish time, take each that starts after the last chosen finishes. Why: finishing earliest leaves the most room for the rest. (Sorting by start time or shortest length is wrong — find counter-examples!)

int maxMeetings(vector<pair<int,int>> m) {           // {start, end}
    sort(m.begin(), m.end(), [](auto& a, auto& b){ return a.second < b.second; });
    int cnt = 0, last = INT_MIN;
    for (auto [s, e] : m) if (s >= last) { ++cnt; last = e; }
    return cnt;
}

Others: Huffman coding (merge the two least frequent), fractional knapsack (best value/weight first), Kruskal/Prim/Dijkstra (greedy with proofs), minimum platforms, jump game.

for (int mask = 0; mask < (1 << n); ++mask)

17.3 Number theory essentials

Modular arithmetic (answers "modulo 10⁹+7"): (a+b)%m, (a*b)%m are fine termwise; subtraction: ((a-b)%m+m)%m. Division is the odd one: use the modular inverse — by Fermat's little theorem, for prime p, $a^{-1}\equiv a^{p-2} \pmod p$, computed with power(a, p-2, p) (Module 10).

Sieve of Eratosthenes — all primes ≤ N in O(N log log N): cross out multiples of each prime starting from p² (smaller multiples were already crossed by smaller primes).

vector<bool> sieve(int N) {
    vector<bool> isP(N + 1, true); isP[0] = isP[1] = false;
    for (long long i = 2; i * i <= N; ++i)
        if (isP[i]) for (long long j = i * i; j <= N; j += i) isP[j] = false;
    return isP;
}

Others: Euclid GCD (std::__gcd, std::gcd), lcm(a,b)=a/gcd(a,b)*b (divide first to avoid overflow), prime factorisation by trial division to √n, combinatorics nCr with factorial and inverse-factorial tables mod p, Pascal's triangle C(n,r)=C(n−1,r−1)+C(n−1,r).

17.4 String algorithms

Problem: find pattern P (length m) in text T (length n). Naive: O(nm) — after a mismatch it forgets everything it learned.

KMP precomputes, for each prefix of P, the length of its longest proper prefix that is also a suffix (the "failure"/lps array). On a mismatch, instead of restarting, it slides P by exactly the amount that keeps the already-matched part consistent. Total O(n+m).

vector<int> prefixFunction(const string& s) {
    int n = s.size(); vector<int> pi(n, 0);
    for (int i = 1; i < n; ++i) {
        int k = pi[i - 1];
        while (k > 0 && s[i] != s[k]) k = pi[k - 1];   // fall back to a shorter border
        if (s[i] == s[k]) ++k;
        pi[i] = k;
    }
    return pi;
}
// find P in T: compute prefixFunction(P + '#' + T); positions where value == |P| are matches.

Why O(n)? k increases by at most 1 per character and each fall-back decreases it, so total fall-backs ≤ total increases ≤ n (amortised, like the monotonic stack).

Rolling hash: hash of a window updates in O(1): h = h*B + c (mod M); compare hashes first, verify on match (Rabin–Karp). Use a large modulus (or two) and a random base to avoid collisions. Z-function, Manacher (all palindromes in O(n)) and suffix arrays are the next steps.

18.2 How to attack a new problem (the Feynman method for algorithms)

  1. Restate it in your own words. Draw a tiny example by hand and solve it as a human.
  2. Brute force first. What's the dumbest correct solution? Compute its complexity.
  3. Check constraints (table in §9.1) — how fast must you be?
  4. Find the waste. Where does brute force repeat work or look at useless candidates? Repeated work → DP/prefix sums/hashing. Search for a value → sort/binary search. Order matters → greedy/heap. Connections → graph.
  5. Pattern-match the toolbox: sorting + two pointers, sliding window, prefix sums, binary search on answer, monotonic stack, BFS/DFS, DSU, DP, greedy-with-proof, bitmask.
  6. Prove it (invariant / exchange argument) before coding.
  7. Test edge cases: n=0/1, all equal, sorted, reverse sorted, max size, negatives, overflow.
  8. Stress test: write the brute force too, generate random small inputs, compare. This finds bugs nothing else will.

18.3 Debugging

  • Compile errors: read the first error only; later ones are often consequences.
  • Wrong answer: print intermediate values; shrink the failing input; assert your invariants (assert(x >= 0);).
  • Segfault: out-of-bounds, null pointer, or infinite recursion. Compile with -fsanitize=address,undefined -g — it names the line.
  • TLE: recount complexity; look for hidden O(n) (erase on vector front, string +, copying vectors in a loop, endl).
  • Overflow: multiply as long long; 1LL * a * b.

void rotateRight(vector<int>& a, int k) {
    int n = a.size(); if (!n) return; k %= n;
    reverse(a.begin(), a.end());
    reverse(a.begin(), a.begin() + k);
    reverse(a.begin() + k, a.end());
}
